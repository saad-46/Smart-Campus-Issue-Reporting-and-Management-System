# SUES campus dataset (Mount Pleasant, Banjara Hills, Hyderabad)

The campus geography the app draws and reports against. It is plain JSON, kept in version control and read at build time; the app makes no geocoding or map request at run time.

How the data was researched, what each source supports and what could not be established is in [docs/SUES_CAMPUS_RESEARCH.md](../../../docs/SUES_CAMPUS_RESEARCH.md).

| File | Contents |
| --- | --- |
| `campus.json` | Campus id, official address, centre, drawing viewport, and why no boundary is asserted |
| `institutions.json` | The seven society institutions at Mount Pleasant, and those elsewhere (listed, never mapped) |
| `locations.json` | `places` (map anchors with coordinates and a precision radius) and `locations` (what a person can report against; `placeId` is `null` when the position is unknown) |
| `research-sources.json` | Every source cited by a record, with what it supports |
| `geometry.json` | OpenStreetMap footprints, roads, paths, gates and green areas as GeoJSON, generated by `scripts/import-osm-campus.mjs` |

## Rules for editing

- Every place and location needs `verificationStatus` and at least one `sourceIds` entry that exists in `research-sources.json`. The meanings of the statuses are in `locations.json` (`statusMeanings`).
- Do not mark a position `verified` without an official source for both what the place is and where it is. Today no position is.
- Do not add floors, room numbers, laboratory counts or building uses that a public source does not state. People type those themselves when reporting.
- Do not name an OpenStreetMap footprint. They stay "Mapped building A–F" until someone confirms on site which block is which.
- Ids are stable: QR codes and stored issues refer to them. Retire a location with `"isActive": false`; never reuse or rename an id.
- Coordinates are WGS84. GeoJSON uses `[longitude, latitude]`; `places` use named `latitude` / `longitude` fields.
- Do not add restricted or security-sensitive places (CCTV, server rooms, guard posts, hostel room lists).

`npm test` runs `tests/unit/campusData.test.ts`, which enforces these rules.

## Refreshing the map geometry

1. Download an Overpass extract for the area (one request, by hand):

   ```
   [out:json][timeout:60];(nwr(17.4235,78.4385,17.4325,78.4500););(._;>;);out body qt;
   ```

2. `node scripts/import-osm-campus.mjs path/to/extract.json`
3. `npm test`, then look at `/viewer/map`.

The current extract has OSM base timestamp `2026-10-09T06:11:06Z`.
